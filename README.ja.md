Unicode Standard Annex #14（UAX #14）が定める[Unicode改行アルゴリズム](https://www.unicode.org/reports/tr14/)を、ネイティブ依存のない純粋なC#で実装したライブラリです。
Unicodeのテキストについて、行を折り返せる位置と、改行が必須の位置を判定します。準拠対象はUnicode 17.0.0とUAX #14 Revision 55です。
入力がUTF-16でもUTF-8でも、マネージド割り当てを一切行わずに動作するため、走査にガベージコレクターは関与しません。ライブラリ全体をNative AOT向けに注釈しています。
正しさは、仕様を読むことではなく、Unicode 17.0.0の公式のLineBreakTest.txtにあるすべての境界との比較で確認しています。

## 概要

Uax14Netは、Unicodeテキストの改行機会を判定します。行を折り返せる位置をすべて報告し、そのうち、ラインフィード、キャリッジリターン、フォームフィード、ネクストラインといった強制改行によって改行が必須となる位置には、その印を付けます。

公開APIはモダンなC#の書き方です。テキストは`ReadOnlySpan<char>`か、UTF-8の`ReadOnlySpan<byte>`で渡します。改行機会は`ref struct`の列挙子が返すため、文書全体をヒープを使わずに走査できます。個々の改行機会は、オフセットと種別を持つ`readonly struct`です。コードポイントの改行クラスは、静的メソッド1つで取得できます。テーラリングは`readonly struct`のオプションで指定し、複合文脈クラスの解決は公開された接合部になっています。状態を持つ走査器は公開していません。

すべての改行クラスと、規則が参照する補助プロパティは、ビルド時に二段のルックアップトライにまとめます。ソースジェネレーターが、追加ファイルとして渡されたUnicode Character Databaseのファイルを読み、トライを静的な読み取り専用データとして出力します。そのため、分類のために実行時に解析する処理も、静的初期化の費用もありません。

Unicodeのデータは本リポジトリに同梱していません。`reference`配下の参照ハーネスが、版を固定したUnicode 17.0.0のデータファイルをダウンロードし、バージョンヘッダーを確かめて`reference/data`に書き出します。ソースジェネレーターはそのファイルからトライを作り、テストは同じ場所から公式のLineBreakTest.txtを読み込んで走査器と比べます。

## 導入方法

```sh
dotnet add package Uax14Net
```

1. ソースからビルドする前に、`reference/build.sh`を実行してUnicode 17.0.0のデータを取得してください。Windowsでは`reference/build.bat`を実行します。ソースジェネレーターは分類トライを作るために、テストはLineBreakTest.txtを読むために、このデータを必要とします。
2. `LineBreaker.Enumerate`にテキストを渡し、改行機会を列挙します。テキストは`ReadOnlySpan<char>`で受け取るため、`string`、配列、スライスをコピーせずに渡せます。
3. 各改行機会は、UTF-16のオフセットと種別として読みます。Allowedは行を折り返せる位置、Mandatoryは改行が必須の位置です。
4. サンプルアプリケーションのNative AOTバイナリを作る場合は、`publish-aot.bat`を実行してください。

## 主な機能

### 1. 改行機会と必須の改行

走査器は、改行機会ごとに結果を1つ返します。アルゴリズムが改行を許す位置と、要求する位置が報告の対象です。改行が禁止される位置は報告しないので、テキストを折り返す側は、実際に使える候補だけを列挙できます。

必須の改行は、規則LB4とLB5の強制改行から生じます。対象は、ラインフィード、キャリッジリターン、ネクストライン、そして垂直タブとフォームフィードを含む強制改行のクラスです。キャリッジリターンにラインフィードが続くときは、2つではなく1つの改行として扱います。テキストの終端は、規則LB3に従い、必須の境界として1回だけ報告します。

### 2. 改行クラスとその解決

すべてのコードポイントに、Unicode 17.0.0の49個の改行クラスのどれか1つを割り当てます。規則LB1に従い、規則を適用する前に解決しておくクラスは、既定で次のように解決します。AI（Ambiguous）、SG（Surrogate）、XX（Unknown）はAL（Alphabetic）に、CJ（Conditional Japanese Starter）はNS（Non-starter）に解決します。SA（Complex-context Dependent）は、一般カテゴリがMnまたはMcならCM（Combining Mark）に、それ以外ならALに解決します。

クラスだけでは決まらない規則も、すべて実装しています。東アジアの文字幅は、規則LB19aの引用符と、規則LB30の括弧の扱いを分けます。一般カテゴリは、引用符の規則LB15a、LB15b、LB19で、Pi（Initial_Punctuation）とPf（Final_Punctuation）を区別します。ブラーフミー系文字のクラスは、点線の円（U+25CC）を含む、Orthographic Syllableの規則LB28aで使います。Regional Indicatorは規則LB30aで2つずつ組にし、Emoji BaseとEmoji Modifierは規則LB30bで結び付けます。数字の規則LB23からLB25は、数字と、その前置記号、後置記号、区切り記号を離さないようにします。

規則LB1が解決するクラスは、`LineBreakOptions`でテーラリングできます。Strictnessは、CJの小書き仮名を前の文字に付けたままにするか、その前で改行を許すかを選びます。AmbiguousWidthは、曖昧な文字（AI）をALとID（Ideographic）のどちらに解決するかを決めます。`WordBreakMode`にはBreakAllとKeepAllがあります。ClassOverrideのデリゲートは、任意のコードポイントの改行クラスを付け替えます。複合文脈クラスの解決には公開された接合部があり、`IComplexContextResolver`が、複合文脈の文字が続く最大の区間を受け取って、その中の改行を報告します。これを使うと、タイ語、ラオ語、クメール語、ビルマ語の辞書による分割器を差し込めます。Resolverを与えないときの既定の解決は、一般カテゴリに従ってCMかALを割り当て、そのような区間の中には改行を入れません。

### 3. 結合文字、Joiner、空白

結合文字列は、規則LB9に従って、その基底文字として扱います。基底文字に続く結合文字やZero Width Joinerは、基底文字に含めて扱うので、その手前で改行することはありません。テキストの先頭、空白、強制改行のあとにあるために基底文字を持たない結合文字は、規則LB10により、ALとして扱います。

Zero Width Joinerは、規則LB8aにより、その直後の改行を禁止します。これによって、Zero Width Joinerでつないだ絵文字の列が分かれません。Word Joinerは、規則LB11により、前後どちらの改行も禁止します。改行しないクラスは、規則LB12とLB12aが扱います。Zero Width Spaceは、規則LB8により、自身の直後と、それに続く空白の直後に改行機会を作ります。

### 4. 無確保と生成トライ

走査器は`ref struct`です。状態はすべてスタックにあり、分類データは静的な読み取り専用メモリに置かれています。入力がUTF-16でもUTF-8でも、テキストの走査中に配列やオブジェクトを割り当てることはありません。分類はブロックの重複を取り除いた二段トライで、`ReadOnlySpan<byte>`として出力します。ランタイムはこれを、ヒープにコピーせず、アセンブリから直接参照します。複合文脈のResolverを与えたときは、各区間をプールしたバッファに入れて渡します。既定の経路は何も割り当てません。

マネージド割り当てが無いことは、主張ではなく計測で確かめています。`GC.GetAllocatedBytesForCurrentThread`が示す増分は、多言語のサンプルをUTF-16とUTF-8の両方の経路で列挙する間も、Unicodeの範囲のすべてのコードポイントを分類する間も、0バイトです。

### 5. 適合検証

走査器を、Unicode 17.0.0の公式のLineBreakTest.txtと比べています。テストの各行は、コードポイントの並びと、先頭の前と末尾の後を含むすべての境界について、改行する印か改行しない印を示します。テストは、すべての印を再現します。

| 項目 | 一致 |
|---|---|
| LineBreakTest.txtの全19338行 | 完全一致 |
| 先頭と末尾を含む、すべての境界の改行する印と改行しない印 | 完全一致 |
| 追加面をまたぐ、UTF-16オフセットで報告する境界 | 完全一致 |

テストプロジェクトには86個のテストがあり、すべて合格します。適合テストは、公式ファイルの19338ケースすべてを検査します。別のテストは、同じコーパス全体をUTF-8の経路で再生し、バイトオフセットがUTF-16のオフセットと一致することを確かめます。残りのテストの対象は、空文字列、1文字、強制改行と必須の改行、CRとLFの組、追加面のオフセット、絵文字のZero Width Joinerの列、Regional Indicatorの組、孤立サロゲート、コード空間の全体、テーラリングのオプション、複合文脈Resolverの接合部、そしてUTF-16とUTF-8の両方の経路でのマネージド割り当ての不在です。

最適化を守るテストは3種類あります。1つ目は、判定表を導入する前に記録したハッシュで、14通りのオプションの下で、150000本の擬似乱数の列に対する出力を固定します。2つ目は、判定表と規則を比べるテストです。対象は、400000本の乱数の列、乱数の文脈の中の表の全項目、そしてClassOverrideでコードポイント本来と無関係なクラスを与えた400000本の列です。3つ目は、連続する文字をまとめて走査した結果と、1文字ずつ走査した結果を、UTF-16とUTF-8の経路それぞれで、400000本の乱数の列について比べるテストです。

### 6. 性能

アルゴリズムは逐次的な走査です。改行の判定は、その左側にあるクラスと、そこまでに蓄積した状態に依存します。そのため、文字をまたいでベクトル化することはできません。したがって速さの源は、SIMDによる並列化ではなく、コンパクトなトライ、判定表、積極的なインライン化、そして割り当てを行わないことです。

判定表は、クラスの組ごとの判定を保持します。添字は、位置の前のクラスと、後のクラスです。空白のあとでは、空白の前のクラスと、空白のあとのクラスで引きます。判定が、この2つのクラス以外にも依存する場合は、判定表を使わず規則で判断します。たとえば、東アジアの文字幅、先読み、左側に蓄積した状態に依存する場合です。`WordBreak`が`BreakAll`か`KeepAll`のときは、それぞれ専用の判定表を使います。判定表に入れるのは、規則が6000通りの乱数の文脈で評価して、結果が一度も変わらなかった組だけです。種の異なる2回の導出の両方で、同じ結果になった組に限ります。乱数の文脈には、ClassOverrideがコードポイントに与えうる、本来と無関係なクラスも含みます。そのため、東アジアの文字幅のように、クラス以外のコードポイントの性質に結果が依存する組は、規則に任せます。

判定表で決まる範囲では、走査器は連続する文字をまとめて読みます。数字の状態のほかに状態を必要としないクラスの文字が続く間は、ローカル変数の中だけで進み、改行機会を見つけたときか、一般の経路が必要な最初の文字に達したときに戻ります。そのような文字には、引用符、Regional Indicator、ブラーフミー系文字の文字、結合文字があり、判定表が規則に任せている組の2文字目も同じです。AI、CJ、SG、XXのクラス、およびResolverを設定していないときのSAは、規則LB1が割り当てるクラスとして読みます。

1つ目の表は、ワークステーションで取った固定の記録です。再生成しません。

Windows 11上の13th Gen Intel Core i7-1360Pで、サンプルアプリケーションを`x86-64-v3`を基準にNative AOTで発行しています。ラテン文字、CJK、タイ文字、ヘブライ文字、数字、約物、引用符、絵文字、Regional Indicatorを含む630784コードポイントの多言語コーパスについて、ビルドを交互に走らせた16プロセスで各30回、合計480回のうち最良の値です。

## APIリファレンス

```csharp
using Uax14Net;

foreach (LineBreakOpportunity op in LineBreaker.Enumerate("The quick brown fox"))
{
    if (op.IsMandatory)
    {
        Console.WriteLine($"mandatory break at {op.Position}");
    }
    else
    {
        Console.WriteLine($"allowed break at {op.Position}");
    }
}
```

### 列挙

| メンバー | 説明 |
|---|---|
| `LineBreaker.Enumerate(ReadOnlySpan<char>)` | UTF-16テキストの改行機会を走査する、`ref struct`の列挙子を返します。 |
| `LineBreaker.Enumerate(ReadOnlySpan<char>, in LineBreakOptions)` | 上と同じで、テーラリングのオプションを指定します。 |
| `LineBreaker.Enumerate(ReadOnlySpan<byte>)` | UTF-8テキストを走査し、バイトオフセットを報告します。 |
| `LineBreaker.Enumerate(ReadOnlySpan<byte>, in LineBreakOptions)` | 上と同じで、テーラリングのオプションを指定します。 |
| `LineBreakEnumerator`、`Utf8LineBreakEnumerator` | `ref struct`の列挙子です。`GetEnumerator`、`MoveNext`、`Current`、`Dispose`を持ちます。 |

列挙子は、改行を許す位置と要求する位置のそれぞれについて、改行機会を1つずつ返します。改行が禁止される位置は飛ばします。空でないテキストの最後の改行機会は、テキストの長さと等しいオフセットにあり、常に必須です。空のテキストでは、改行機会を1つも返しません。UTF-16の列挙子はUTF-16のオフセットを、UTF-8の列挙子はバイトオフセットを報告します。不正なUTF-8は置換文字として復号します。

### 改行機会

| メンバー | 説明 |
|---|---|
| `LineBreakOpportunity.Position` | 行を折り返せるオフセットです。UTF-16の列挙子はUTF-16のコード単位の、UTF-8の列挙子はバイトのオフセットを返します。改行は、このオフセットにあるコード単位かバイトの前に入ります。 |
| `LineBreakOpportunity.Kind` | `LineBreakKind.Allowed`か`LineBreakKind.Mandatory`です。 |
| `LineBreakOpportunity.IsMandatory` | 強制改行かテキストの終端によって、改行が必須のときtrueです。 |

`LineBreakKind`は`Allowed`と`Mandatory`の2つです。Allowedは折り返しの候補で、Mandatoryは、使える幅にかかわらず守らなければなりません。

### クラス

| メンバー | 説明 |
|---|---|
| `LineBreaker.GetLineBreakClass(int)` | Unicodeスカラー値の`Line_Break`プロパティ値を返します。 |
| `LineBreakClass` | Unicode 17.0.0の49個の改行クラスです。 |

`GetLineBreakClass`は、Unicode Character Databaseに記録されたプロパティ値を、規則LB1で解決する前の状態で返します。Unicodeの範囲外のコードポイントは、XXになります。

### テーラリング

`LineBreakOptions`は、`init`アクセサーを持つ`readonly struct`です。`LineBreakOptions.Default`は、適合テストが検証する、素のUAX #14の既定です。

| メンバー | 既定値 | 説明 |
|---|---|---|
| `Strictness` | `Strict` | `Strict`は小書き仮名をNSとして前の文字に付け、`Normal`はCJをIDに解決して、小書き仮名の前で改行を許します。 |
| `WordBreak` | `Normal` | `BreakAll`は、テーラリングできない規則が許すすべての位置で改行を許します。`KeepAll`は、ID文字どうしの間の改行を抑えます。 |
| `AmbiguousWidth` | `Alphabetic` | 曖昧なクラス（AI）を、ALとIDのどちらに解決するかを選びます。 |
| `ClassOverride` | `null` | 規則LB1の前に、コードポイントの改行クラスを付け替えるデリゲート（`int -> LineBreakClass?`）です。 |
| `ComplexContextResolver` | `null` | 複合文脈の文字が続く区間を分割する、`IComplexContextResolver`です。 |

`ClassOverride`のデリゲートは、同じコードポイントについて複数回呼ばれることがあります。そのため、毎回同じ値を返してください。`LineBreakClass`の定義にない値を返すと、列挙は`InvalidOperationException`を投げます。ClassOverrideで複合文脈のクラスに移したコードポイントはResolverの対象になり、複合文脈のクラスから外したコードポイントは対象になりません。

`IComplexContextResolver.Resolve(ReadOnlySpan<char> run, Span<bool> breakBefore)`は、複合文脈の文字が続く最大の区間ごとに1回呼ばれます。`breakBefore[i]`をtrueにすると、`run[i]`の前で改行できます。ただし`breakBefore[0]`は効果がありません。区間の先頭の文字の前は、規則が決めるためです。テーラリングできない規則が禁じる改行は、エンジンが無視します。そのため、Resolverが規則に反する結果を作ることはできません。ResolverはUTF-16の入力にだけ使われ、UTF-8の入力では既定の解決を使います。

## 制限事項

- 文字幅の測定、指定した行幅に収まる改行の選択、描画、ハイフネーション、言語ごとの辞書による分割は、このライブラリの対象外です。ライブラリが報告するのは改行機会です。特定の幅に対してどこで折り返すかは、レイアウトエンジンが選びます。
- 複合文脈のスクリプト用の辞書は含みません。Resolverを与えない場合、タイ語、ラオ語、クメール語、ビルマ語などは、空白でだけ改行します。これはUAX #14の既定です。辞書による分割器は`IComplexContextResolver`で与えられます。ライブラリが用意するのは接合部であり、辞書ではありません。この接合部が使えるのは、UTF-16の入力だけです。
- テキストはspan全体で処理します。別々に渡したチャンクにまたがる逐次的な改行判定は、できません。複数の規則の先読みが、チャンクの境界を越えるためです。
- クラスの割り当てと規則は、Unicode 17.0.0とUAX #14 Revision 55に従っています。別のUnicodeバージョンを使うには、対応するデータファイルからトライを作り直す必要があります。
- ソースからのビルドには、Unicodeのデータファイルが必要です。`reference/data`がないと、ソースジェネレーターはトライを作れず、適合テストも実行できません。
- `Uax14Net.Examples`のサンプルアプリケーションはコンソールに書き込むため、マネージドメモリを割り当てます。割り当てをしない保証が当てはまるのは、ライブラリです。

## 注意事項

- 入力のエンコーディング: UTF-16の入力ではUTF-16のコード単位のオフセットを、UTF-8の入力ではバイトオフセットを報告します。サロゲートペアは、上位サロゲートのオフセットにある1つのスカラー値として扱います。孤立サロゲートはSGクラスの1つの単位として扱い、不正なUTF-8の並びは、正しい並びの先頭として読める最も長い部分ごとに、1つの置換文字として復号します。これはUnicodeの推奨で、`Rune.DecodeFromUtf8`も同じです。
- 決定性: 走査は、繰り返し実行しても同じ出力になり、呼び出しの間で状態を持ちません。列挙子は、呼び出し側が持つspanに対する`ref struct`なので、別々の列挙は互いに独立していて、インスタンスを共有しません。
- 列挙子の寿命: Resolverを使うと、列挙子は共有の配列プールからバッファを借り、`Dispose`で返します。列挙子の`Dispose`は1回だけ呼んでください。コピーどうしがバッファを共有するため、元の列挙子が進んだあとは、そのコピーを使わないでください。`foreach`はこの決まりどおりに動きます。
- 解決の接合部: 規則LB1の解決は、規則のエンジンから分離してあります。そのため、テーラリングのオプションと複合文脈のResolverは、テーラリングできない規則に触れずに、クラスの割り当てと、区間の中の改行を変えられます。
- 判定表: `Uax14Net/LineBreakPairTable.cs`は規則から導いたもので、テストが規則と比べています。規則を変えたあとに再生成する手順は、[貢献の手引き](https://github.com/routersys/Uax14Net/blob/main/CONTRIBUTING.ja.md)に書いてあります。
- Native AOT: ライブラリは`IsAotCompatible`を設定しているので、トリミング、単一ファイル、AOTのアナライザーが有効です。`publish-aot.bat`はサンプルアプリケーションを`win-x64`向けに発行します。ネイティブリンカーのために、MSVCのツールセットが必要です。
- 参照データの再生成: `reference/build.sh`と`reference/build.bat`は、Unicode 17.0.0のデータファイルをダウンロードし、バージョンヘッダーを確かめて、`reference/data`に書き出します。このディレクトリはバージョン管理に含めません。
